Why Heimdall exists

An investigation should not begin with tool wrangling.

Incident response is time-sensitive, yet the evidence often ends up scattered: event logs in one tool, memory in another, a timeline assembled by hand and notes stored separately.

Hosted commercial platforms can simplify that workflow, but they may not fit cases where logs, memory dumps or client evidence must remain on infrastructure you control.

  • ✕Separate tools show different parts of the same incident.
  • ✕Manual exports and copy-paste make timelines slow to build and hard to reproduce.
  • ✕Case context is easy to lose when artifacts, hosts and notes are stored apart.
  • ✕Cloud-first platforms may conflict with evidence-handling requirements.
  • ✕Email and screenshots do not provide a useful investigation record.
Approach

A case workspace you can host yourself

Heimdall keeps analysis and case records together while leaving deployment and data handling in your hands.

Self-hosted deployment

bash start.sh starts the stack on infrastructure you manage.

No product telemetry

Heimdall does not include usage analytics or require a hosted account. External integrations run only when you configure them.

Case-scoped data

Artifacts, timelines, memory results, network activity and detections remain attached to the case they came from.

Optional local assistant

The Ollama assistant runs on your deployment and can be left disabled when a case does not call for it.

Reviewable history

UTC timestamps and a tamper-evident audit chain help reviewers trace sensitive case actions.

Open source

The project is MIT-licensed, so teams can inspect and adapt the code they run.

Capabilities

What Heimdall includes

The main investigation tasks are available from the same case workspace.

Cases & evidence

Store evidence, notes, hashes and sensitive-action history against the relevant investigation.

Artifact parsing

Drop a KAPE, Velociraptor or CyLR archive. EVTX, MFT, Prefetch, LNK, Shellbags, Amcache and registry data are processed with EZTools and Hayabusa.

Super Timeline

Review artifacts in a shared timeline with dynamic columns, grouping, filters, search, bookmarks and CSV export.

Threat hunting

YARA, Sigma, Hayabusa, TAXII/STIX feeds, IOC enrichment and confidence scoring across one evidence item or the whole case.

Memory forensics

Use VolWeb and Volatility 3 to examine processes, connections and other traces in memory images stored through MinIO.

Network & lateral movement

Interactive graph, 4624/4648/Kerberos events, beaconing, DGA and MITRE ATT&CK context when the logs support it.

Local assistant

When enabled, Ollama uses available case context to answer questions and prepare a report draft on the local deployment.

Notes & reports

Notes, pins, analyst presence and forensic PDF generation with section selection.

Knowledge base

Built-in docs for Windows/Linux artifacts, Event IDs, attack patterns and tooling cheat sheets.

Workflow

A three-step case workflow

01

Collect & import

Generate a collection agent or drop a KAPE / Velociraptor / CyLR archive. Heimdall detects and parses the artifacts on ingest.

02

Correlate & hunt

Use the Super Timeline, run YARA and Sigma rules, and review network and lateral-movement views. The local assistant can help summarise available context, but the analyst remains responsible for the finding.

03

Document & export

Pin supporting evidence, add analyst notes and generate a forensic PDF. Sensitive actions remain visible in the case audit history.

Security & privacy

Deployment and evidence controls

The platform is designed for case data that must remain on infrastructure managed by the investigating team.

Self-hosted stack

The application services run on your server through Docker Compose. Optional external integrations remain under administrator control.

No product telemetry

Heimdall does not send analytics, usage metrics or crash reports. Features that contact third-party services must be configured separately.

Tamper-evident audit chain

Sensitive evidence actions are linked by hashes so reviewers can detect some forms of modification or deletion. This supports, but does not by itself guarantee, chain of custody.

Access controls

Role-based permissions, JWT sessions, inactivity logout and configurable retention settings help administrators limit access to case data.

FAQ

Common questions

Is it free to use?
Yes. Heimdall is released under the MIT license and does not have per-seat fees or paid modules. Check the licenses of integrated third-party tools if you plan to redistribute a deployment.
Do I need a GPU?
No. The optional Ollama assistant can run in CPU mode with a lightweight model such as qwen3.5:4b. A supported GPU improves inference speed but is not required for the rest of Heimdall.
Which artifacts does it parse?
Windows EVTX, MFT, Prefetch, LNK, Shellbags, Amcache, registry hives, USN journal, UserAssist and more, automatically on import (EZTools · Hayabusa). Memory images are handled by Volatility 3 / VolWeb. Network activity is reconstructed from Sysmon and event logs.
Is my data sent anywhere?
The core platform is self-hosted and has no product telemetry. Optional services, including threat-intelligence enrichment, may contact providers configured by an administrator. Review those settings before working with sensitive evidence.
Is it production-ready?
Heimdall is still in Beta. Test it against your own requirements before using it on a critical engagement, maintain independent backups and review the roadmap for work planned before 1.0.
What do I need to run it?
Docker and Docker Compose on a single host. bash start.sh starts the services and generates secrets on first run. Elasticsearch and an optional Ollama model use the most memory, so size the host for the components you enable.
The mission

I started Heimdall because I wanted the tools I already used to share the same case context. The project brings those workflows together while keeping deployment and evidence handling under the investigator's control.
